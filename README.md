# vibalert — 连续越界告警库

Go 进程内告警库：每个 `Monitor` 实例处理一台资产的一路振动读数，
依据**采样序号顺序**（而非上传顺序）识别连续越界段并维护告警。
支持离线补传与历史更正，告警随最新完整数据同步修正。

## 业务规则

- 创建时指定振动上限 `limit` 与连续次数 `k`（1–100000），之后不变。
- 振动值**严格大于**上限才算越界；等于上限算正常。
- 读数按采样序号组织，序号可有缺口，缺口不补点、不打断连续性；
  同一序号再次写入视为更正（替换旧值）。
- 连续越界且不能向两端延伸的一段称为越界段；段内读数 ≥ k 时产生
  且仅产生一个告警。告警记录：起始序号、首次达到 k 条时的触发序号、
  末尾序号、读数数量。告警身份由起始序号决定。
- 每次 `Write` 返回相对调用前状态的净差分（新增/更新/撤销），
  不暴露批内中间状态；原样重放同一批数据差分为空。

## API

```go
m := vibalert.New(10.0, 3)          // 上限 10，连续 3 次
diff := m.Write([]vibalert.Reading{ // 批量写入或更正
    {Seq: 100, Value: 11.5},
    {Seq: 101, Value: 12.0},
    {Seq: 105, Value: 13.0},
})
// diff.Added / diff.Updated / diff.Removed （均按起始序号排序）
alerts := m.Alerts()                // 当前全部告警，按起始序号排序
```

## 实现要点

- 读数与越界段各用一棵带子树大小的随机化笛卡尔树维护，
  单点写入/更正为 O(log n)，只触及相邻越界段；
  告警按身份（起始序号）增量维护，批内变化合并为净差分。
- 全部数据保存在进程内存，无外部依赖，无网络与磁盘 I/O。

## 运行测试

```sh
go test ./...            # 全部功能测试 + 性能测试
go test -run TestPerf -v # 只看性能测试报告
```

功能测试覆盖：乱序补录合并两个告警、正常读数插入长段后又被更正
导致的分裂再合并（校验告警身份与触发点）、同批数据不同排列的
净差分一致性与重放幂等、随机小批量写入与独立全量计算逐批核对。

性能测试（perf_test.go）：100 万条历史读数装载后连续 2 万次单点
补录/更正，包含 K=100000 长段前部补录与段中部反复更正、以及约
25 万个短段的场景，断言总耗时 ≤ 20 s、峰值内存 ≤ 512 MiB，
并通过 `t.Log` 报告实测值（本机实测约 12–38 ms、107–170 MiB）。
