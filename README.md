# vibralert — 连续越界告警库

Go 进程内告警库：每个 `Monitor` 实例处理一台资产的一路振动读数，
按**采样顺序**（而非上传顺序）识别连续越界，支持离线补传与历史更正，
告警随最新完整数据同步修正。

## 规则摘要

- 创建时指定振动上限 `limit` 与连续次数 `K`（1..100000），之后不变；
  振动值**严格大于**上限才算越界。
- 读数按采样序号有序，序号可有缺口（缺口不补点、不打断连续性）；
  同一序号再次写入即更正。
- 连续越界且不能向两端延伸的一段称为越界段；段内读数 ≥ K 时产生且仅产生一个告警。
- 告警记录：起始序号、首次达到 K 条的触发序号、末尾序号、读数数量；
  身份由起始序号决定（起始变化 = 旧告警撤销 + 新告警产生）。
- 每次批量写入返回相对调用前的净差分（新增/更新/撤销），
  不暴露批内中间状态；原样重放同一批数据差分为空。

## API

```go
m := vibralert.NewMonitor(100.0, 3)      // 上限 100，连续 3 次
changes := m.ApplyBatch([]vibralert.Reading{
    {Seq: 10, Value: 120.5},
    {Seq: 11, Value: 130.0},
    {Seq: 12, Value: 110.0},
})
// changes: [{Kind: added, Alert: {StartSeq:10 TriggerSeq:12 EndSeq:12 Count:3}}]
alerts := m.Alerts()                     // 当前全部告警，按起始序号排序
```

- `NewMonitor(limit float64, k int) *Monitor`
- `ApplyBatch(readings []Reading) []AlertChange` — 批量写入/更正（同批序号唯一，允许乱序），返回净差分
- `Alerts() []Alert` — 当前全部告警，按起始序号升序

非并发安全；调用方按顺序调用即可。无外部依赖，仅使用标准库。

## 实现要点

- 读数与越界段各用一棵带子树大小的 treap（有序统计树）维护，
  单点写入/更正为 O(log n)，段合并/分裂只触及局部。
- 差分按告警起始序号累积批内净变化：段被修改/删除前记录旧告警并置空新告警，
  段创建/变化后记录新告警，批末对比生成新增/更新/撤销。

## 运行测试

```sh
go test ./...          # 全部单元测试 + 性能测试
go test -run TestPerf -v ./...   # 只看性能测试（耗时与峰值内存）
```

性能测试覆盖验收规模（本机 Go 1.27, Apple Silicon 实测）：

- `TestPerfLongSegment`：K=100000，100 万条历史为一个长越界段；
  2 万单点批（长段前部补录 + 段中部反复更正）约 17 ms，峰值堆内存约 100 MiB。
- `TestPerfManyShortRuns`：25 万个短越界段；2 万单点批约 64 ms，峰值堆内存约 173 MiB。

均远低于 20 秒 / 512 MiB 的限制。
